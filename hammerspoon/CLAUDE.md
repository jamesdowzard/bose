`bose.lua` is dofile'd from this repo path by `~/.hammerspoon/init.lua`.
Edits apply on Hammerspoon reload (`hs -c 'hs.reload()'`).

- `hammerspoon/bose.lua` -- Hammerspoon module, all **event-driven** (no timers). **Only Opt+B is bound now** (2026-06-20): **Opt+B shows/hides the Bose app** (the windowed control surface — press once to open/focus, again to hide; switch devices/ANC/EQ from its tiles). The other four hotkeys are **commented out in `start()`** — James drives everything else from the Bose app (Opt+I was cycling spatial audio unexpectedly). Their binds + `_MODS`/`_KEY` defaults remain in the file, so re-enabling any is a one-line uncomment + reload: **Opt+⇧B toggles Mac ↔ phone** (+ one-shot low-battery warn piggybacked on the press), **Opt+N cycles ANC** (quiet→aware→immersion), **Opt+I cycles Immersive Audio** (off→still→motion; custom modes only — shows a hint on a fixed named mode), **Opt+J connects the headphones to this Mac** (unconditional, no toggle direction-guessing; `CONNECT_TARGET` retargets it). Plus one live **OS-event** behaviour (no hotkey, no poll): **auto-route on call** — a call app (Teams/Zoom/FaceTime/Slack/Webex) launching routes the Mac's *input* to the MacBook mic (the over-ear mics make callers hear the room); no restore on quit (`terminated` unreliable, 2026-06-20). `AUTO_ROUTE_ON_CALL` + `CALL_APPS`. Two flags **off since 2026-08-27**: `MIC_LOCK` (the ex-unconditional guard forcing input off the Bose — it ignored `CALL_APPS` so it also caught WhatsApp calls) and `ANNOUNCE_BATTERY`. Both false ⇒ the audiodevice watcher never starts; app-launch routing is unaffected. NB Teams can override the system input with its own setting — set its in-app mic once. Returns a table with `.start()`/`.stop()`. Wired in `init.lua` via `BoseCtl = dofile(os.getenv("HOME").."/code/personal/bose/hammerspoon/bose.lua"); BoseCtl.start()`. Edits apply on Hammerspoon reload.
